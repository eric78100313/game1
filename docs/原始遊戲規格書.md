# 遊戲開發規格書

## 一、遊戲基本資訊

**遊戲名稱：** Project Last Bastion（最後堡壘：地下研究基地防衛戰）

**遊戲類型：** 3D 第一人稱射擊（FPS）、多人合作、基地防守、波次生存

**遊戲平台：** 電腦網頁瀏覽器

**開發技術：** HTML、CSS、JavaScript、Three.js

**部署方式：** GitHub Pages

**檔案要求：** 最終網頁整合為單一 `index.html`，CSS 與 JavaScript 直接寫入 HTML，允許透過 CDN 載入 Three.js 等必要函式庫。

## 二、遊戲概念與目標

本遊戲是一款黑暗像素風格的 3D 第一人稱多人合作射擊遊戲。

遊戲背景設定在遭到敵人入侵的地下研究基地。玩家需要與隊友合作，使用各種槍械、防禦建築及特殊技能，抵擋殭屍、機器人、怪物及敵軍的進攻，保護基地內的重要設施。

玩家可以透過擊殺敵人、完成波次與防守任務獲得資源，並利用商店購買武器、升級裝備、建造防禦設施及維修基地。

遊戲共有三個關卡，每關包含十波敵人，並設有 Boss 戰。玩家必須完成各關卡任務，保護中央能源核心不被摧毀，最終擊敗大型 Boss 才能通關。

遊戲支援單人遊玩與最多四人合作，目標通關時間約為 15–20 分鐘。

## 三、遊戲畫面與操作方式

### 3.1 遊戲畫面

- 採用完整 3D 第一人稱視角。
- 玩家能自由移動、轉向、跳躍、奔跑、蹲下及滑鏟。
- 使用黑暗像素風格，結合低多邊形模型與低解析度貼圖。
- 場景包含地下研究基地、實驗室、能源核心控制區、走廊、房間及障礙物。
- 使用昏暗燈光、紅色警報燈、爆炸、槍口火光與受擊特效營造戰鬥氛圍。
- 玩家畫面中央具有準心，底部呈現目前持有的武器。

### 3.2 玩家操作

| 操作 | 按鍵 |
|---|---|
| 前後左右移動 | W / A / S / D |
| 控制視角 | 滑鼠 |
| 射擊 | 滑鼠左鍵 |
| 瞄準 | 滑鼠右鍵 |
| 換彈 | R |
| 奔跑 | Shift |
| 蹲下／滑鏟 | Ctrl |
| 跳躍／二段跳 | Space |
| 切換武器 | 1、2 |
| 與設施互動 | E |
| 使用特殊技能 | Q |
| 投擲手榴彈 | G |
| 放置防禦建築 | F |
| 查看地圖與隊伍 | Tab |
| 開啟建築／補給選單 | B |
| 開啟選單／解除滑鼠鎖定 | Esc |

### 3.3 玩家基本屬性

- 初始生命值：100 HP。
- 初始護甲：50。
- 普通移動速度：5 m/s。
- 奔跑速度：8 m/s。
- 可以二段跳。
- 滑鏟持續 0.8 秒，冷卻時間 3 秒。
- 玩家死亡後等待 8 秒重新生成。
- 玩家一次最多攜帶兩把武器。
- 玩家受到攻擊時會扣除生命值，護甲優先承受傷害。
- 生命值歸零時播放死亡效果，並進入重生倒數。

## 四、槍械與射擊系統

遊戲提供六種槍械，每種武器具有不同的傷害、射速、彈匣容量、射程及換彈速度。

| 武器 | 基礎傷害 | 射速 | 彈匣容量 | 換彈時間 |
|---|---:|---:|---:|---:|
| 手槍 | 25 | 3 發/秒 | 12 | 1.3 秒 |
| 突擊步槍 | 18 | 9 發/秒 | 30 | 2 秒 |
| 霰彈槍 | 9 × 8 彈丸 | 1 發/秒 | 8 | 3 秒 |
| 狙擊槍 | 110 | 0.8 發/秒 | 5 | 2.8 秒 |
| 衝鋒槍 | 12 | 13 發/秒 | 40 | 1.8 秒 |
| 火箭筒 | 140 | 0.5 發/秒 | 1 | 3.5 秒 |

### 4.1 射擊機制

- 使用滑鼠控制準心方向。
- 左鍵射擊，右鍵進入瞄準模式。
- 每種武器具有不同程度的後座力。
- 射擊時減少彈匣中的子彈數量。
- 彈匣用盡後需要換彈，換彈期間無法射擊。
- 命中敵人身體與頭部會造成不同傷害。
- 一般槍械爆頭傷害為 1.8 倍，狙擊槍為 2 倍。
- 霰彈槍一次發射多顆彈丸，距離越遠越不容易全部命中。
- 火箭筒具有範圍爆炸效果。
- 命中敵人時顯示命中提示與傷害數字。

### 4.2 武器升級

每種武器可以從 Lv.1 升級至 Lv.5，每升一級提高約 12% 的基礎傷害。

玩家可以安裝武器配件，包括：

- 擴充彈匣：增加彈匣容量。
- 穩定握把：降低後座力。
- 快速換彈：縮短換彈時間。
- 瞄準鏡：改善遠距離瞄準。

每把武器最多裝備兩種配件。

## 五、敵人與 AI 系統

遊戲具有四種基本敵人，以及各關卡的 Boss。

| 敵人類型 | 生命值 | 移動速度 | 攻擊方式 |
|---|---:|---:|---|
| 殭屍 | 90 | 3 m/s | 近距離攻擊 |
| 機器人 | 150 | 2.5 m/s | 遠距離射擊 |
| 怪物 | 120 | 6 m/s | 高速衝刺、近戰攻擊 |
| 敵軍 | 100 | 4 m/s | 槍械攻擊、掩體戰術 |
| 小 Boss | 1200 | 2.5 m/s | 特殊攻擊、召喚敵人 |
| 最終 Boss | 3500 | 2 m/s | 多階段攻擊、範圍技能 |

### 5.1 敵人 AI 行為

敵人需要具備基本戰術行為，而不是單純直線靠近玩家。

AI 行為包含：

1. 尋找玩家或重要防守目標。
2. 根據地圖中的道路與障礙物選擇移動路線。
3. 接近攻擊範圍後進行攻擊。
4. 部分敵人會尋找掩體或從側面進攻。
5. 敵人可以優先攻擊受到較少防守的據點。
6. 敵人死亡時播放動畫、移除物件並發放獎勵。
7. Boss 可以根據剩餘生命值切換攻擊階段。

AI 可採用有限狀態機與導航節點實作，不要求訓練機器學習模型。

## 六、基地與防禦系統

每個關卡包含至少五個重要設施。

| 設施 | 初始生命值 | 功能 |
|---|---:|---|
| 中央能源核心 | 1000 | 主要防守目標 |
| 通訊中心 | 400 | 顯示敵人位置 |
| 伺服器室 | 400 | 提供額外資源獎勵 |
| 武器補給站 | 450 | 提供武器與彈藥補給 |
| 防禦控制室 | 450 | 提升自動砲塔能力 |

### 6.1 基地損壞機制

- 敵人可以攻擊基地內的重要設施。
- 各設施具有獨立生命值。
- 除中央能源核心外，其他設施被破壞不會直接導致失敗，但會失去對應功能。
- 玩家可以消耗維修零件修復受損設施。
- 中央能源核心生命值歸零時，所有玩家立即進入失敗畫面。

### 6.2 防禦建築

玩家可以建造以下設施：

- 自動砲塔：自動偵測並攻擊附近敵人。
- 路障與城牆：阻擋敵人前進。
- 地雷與陷阱：敵人接近後觸發傷害。
- 維修工具：修復受損設施。

防禦設施只能放置在合法位置，不能完全阻斷所有敵人的移動路線。

## 七、資源與商店系統

遊戲包含三種資源：

| 資源 | 取得方式 | 用途 |
|---|---|---|
| 金錢 | 擊殺敵人、完成波次 | 購買武器、升級、彈藥 |
| 維修零件 | 波次獎勵、特殊敵人掉落 | 維修基地、建造防禦設施 |
| 特殊能量 | 精英敵人、Boss、特殊任務 | 使用高階特殊技能 |

玩家初始擁有：

- 金錢：500
- 維修零件：50
- 特殊能量：0

### 7.1 商店

- 每波結束後開放完整商店。
- 玩家可以購買武器、配件、防禦設施及升級。
- 戰鬥中可以開啟緊急補給選單。
- 緊急補給僅提供彈藥、醫療與簡易維修。
- 購買商品後即時更新資源數量。
- 資源不足時不可購買。

### 7.2 特殊技能

| 技能 | 效果 | 冷卻／消耗 |
|---|---|---|
| 手榴彈 | 造成範圍爆炸傷害 | 15 秒 |
| 衝刺／閃避 | 快速移動並躲避攻擊 | 8 秒 |
| 醫療技能 | 恢復 40 HP | 25 秒 |
| 敵人減速 | 範圍敵人減速 50%，持續 5 秒 | 30 秒 |
| 空襲支援 | 指定區域造成大量傷害 | 100 特殊能量 |

## 八、關卡與遊戲流程

遊戲總共三個關卡，每個關卡包含十波敵人。

### 第一關：研究基地遭到入侵

主要敵人為殭屍與機器人。

玩家需要熟悉移動、射擊、換彈、維修基地與商店系統，保護能源核心和通訊中心。

第十波出現第一隻小 Boss。

### 第二關：地下實驗室失控

加入怪物與敵軍，敵人會使用衝刺、遠距離攻擊與掩體戰術。

玩家需要在不同房間之間移動，利用路障、砲塔及特殊技能保護基地。

第十波出現第二隻小 Boss。

### 第三關：中央核心最終防線

四種敵人混合進攻，敵人從不同方向同時攻擊據點。

玩家需要合理分配金錢、維修零件與特殊能量，維持基地運作。

第十波出現大型最終 Boss。

擊敗 Boss、清除剩餘敵人，且中央能源核心尚未被摧毀，即完成遊戲。

### 8.1 波次機制

每波包含：

1. 準備階段：玩家購買裝備、維修基地、建造防禦設施。
2. 戰鬥階段：敵人依照波次生成並開始進攻。
3. 波次結算：統計擊殺數、據點血量與資源獎勵。
4. 進入下一波：提高敵人數量、能力或種類。

每波準備時間預設為十秒，所有玩家準備完成後可以提前開始。

每波敵人數量從約五隻逐步增加至二十隻，並透過分批生成避免大量敵人同時造成效能問題。

## 九、多人合作系統

遊戲需要支援單人模式與最多四人的合作多人模式。

### 9.1 房間系統

- 玩家可以建立私人房間。
- 房主建立房間後取得房間代碼。
- 其他玩家可以使用房間代碼加入。
- 等待室顯示所有玩家的名稱與準備狀態。
- 房主負責開始遊戲。
- 預設最多四名玩家。

### 9.2 多人同步

不同玩家必須看到一致的遊戲狀態，包括：

- 玩家位置、移動與射擊動作。
- 敵人位置、生命值與死亡狀態。
- 基地設施生命值。
- 波次與關卡進度。
- 防禦建築狀態。
- Boss 生命值。
- 遊戲勝利與失敗結果。

玩家各自持有個人武器與資源，但共享基地生命值及關卡目標。

預設不開啟隊友傷害。

玩家死亡後等待八秒重生。房主負責統一計算敵人 AI、傷害與重要遊戲狀態。

### 9.3 多人技術需求

- 網頁前端部署於 GitHub Pages。
- 可以使用 WebRTC 或其他即時連線技術。
- 若需要訊號協調或中繼伺服器，可使用外部服務。
- 不能將僅在同一頁面內產生多個角色的模擬功能當作真正多人遊戲。
- 至少需要成功在兩個不同瀏覽器或裝置上測試連線。
- 多人連線失敗時，不能影響單人模式正常使用。

## 十、遊戲介面設計

網頁包含以下主要畫面：

### 10.1 主選單

- 遊戲標題。
- 單人開始遊戲。
- 建立多人房間。
- 加入多人房間。
- 繼續遊戲。
- 遊戲設定。
- 操作說明。

### 10.2 遊戲 HUD

遊戲畫面需顯示：

- 玩家生命值與護甲。
- 目前武器與剩餘彈藥。
- 特殊技能與冷卻狀態。
- 金錢、維修零件、特殊能量。
- 目前關卡與波數。
- 剩餘敵人數量。
- 中央能源核心與重要設施的生命值。
- 小地圖與敵人方向提示。
- 多人模式下的隊友生命與狀態。

### 10.3 其他介面

- 商店與武器升級介面。
- 防禦建築介面。
- 波次結算畫面。
- Boss 血量顯示。
- 死亡與重生倒數。
- 遊戲失敗畫面。
- 通關結算畫面。
- 暫停與設定介面。

## 十一、存檔與進度系統

遊戲需要保存玩家的遊玩進度，包含：

- 已解鎖的關卡。
- 目前關卡與波次。
- 玩家擁有的武器。
- 武器等級與配件。
- 金錢、維修零件與特殊能量。
- 防禦設施與重要據點狀態。
- 個人最高分與最佳成績。

單人模式使用瀏覽器本地儲存，例如 localStorage。

多人模式由房主保存房間進度，其他玩家分別儲存個人設定與永久解鎖資料。多人房間以完成波次時作為存檔點，避免不同玩家的進度發生衝突。

## 十二、技術與部署要求

1. 遊戲使用 HTML、CSS、JavaScript 實作。
2. 使用 Three.js 建立真正可操作的 3D 場景。
3. JavaScript 與 CSS 必須整合於單一 `index.html`。
4. 可以透過 CDN 使用外部 JavaScript 函式庫。
5. 不需要下載安裝遊戲，直接開啟網頁即可操作。
6. 網頁必須能透過 GitHub Pages 公開存取。
7. 單人遊戲不可依賴多人伺服器才能啟動。
8. 多人遊戲可以使用外部即時連線服務，但必須完成真正的跨裝置連線與同步。
9. 應避免大量物件造成明顯卡頓，並加入適當的畫質與效能控制。
10. 遊戲必須有錯誤提示、重新開始與返回主選單功能。

## 十三、功能驗收標準

### 基本遊戲功能

- 網頁可以正常開啟並載入 3D 場景。
- 玩家可以自由移動、跳躍、奔跑、滑鏟及操作視角。
- 玩家無法穿越牆壁或障礙物。
- 六種武器可以射擊、切換、換彈並造成不同傷害。
- 爆頭、後座力、瞄準與爆炸效果正常。
- 敵人能正常生成、移動、攻擊和死亡。

### 防守與關卡系統

- 至少五個防守設施具有獨立狀態。
- 中央能源核心被摧毀時會正確判定失敗。
- 玩家可以使用維修工具及防禦建築。
- 三種資源可以正常取得與使用。
- 商店、武器升級與特殊技能可正常操作。
- 三個關卡各包含十波敵人。
- 每關 Boss 可以正常生成、攻擊與被擊敗。
- 完成全部關卡後顯示通關畫面。

### 多人系統

- 玩家可以建立房間並取得房間代碼。
- 其他玩家可以透過代碼加入同一房間。
- 至少兩名玩家可以在不同裝置上同時操作。
- 玩家位置、射擊、敵人生命與基地狀態能正確同步。
- 玩家死亡與重生可正常執行。
- 房主斷線或連線失敗時有明確提示。

### 介面與存檔

- HUD 能正確顯示玩家狀態與戰鬥資訊。
- 商店、設定及地圖介面可以正常開關。
- 玩家可以重新開始遊戲或返回主選單。
- 遊戲進度能夠保存並重新載入。
- GitHub Pages 公開網址可以正常存取與操作。

## 十四、開發原則

本遊戲採用 Vibe Coding 開發方式，透過 AI 協助撰寫、測試、修改及整合程式。

完整規格為最終開發目標，但實作時應先完成 3D 場景、玩家操作、射擊與敵人系統，再逐步加入基地防守、商店、關卡、Boss、多人連線與存檔功能。

每完成一個系統都需要確認功能正常，不能僅製作視覺介面或使用沒有實際功能的按鈕代替。

如遇到無法立即實作的功能，必須明確指出限制，不可將模擬效果宣稱為已完成的功能。

**最終目標：完成一款能夠透過 GitHub Pages 公開遊玩、具有完整 3D 射擊與基地防守玩法，並支援真正多人合作的網頁遊戲。**
